Joiners, leavers, ownership

What leavers own, know and can access goes unnoticed

Impact: orphaned services, lost knowledge

Agent · ownership-steward

Same pattern for every agent: read-only inputs, numbers computed in code, the agent explains and drafts, a person approves.

Engineering Command Centre · 5 · Qualitative assessment; to be validated with baseline data during the pilot

These six sit between teams rather than inside one. Capacity and DR are about being ready before the bad day. Contracts and data pipelines are about one team's change silently breaking another's. Access and ownership are about what happens when people join, move or leave. The point to land is that none of these needs a new kind of AI: each agent follows the same rules as incident investigation. It reads, code computes, the agent explains and drafts, and a named person approves. For joiners and leavers, stress that the agent looks at ownership and access only, never at individual performance. None of these are in the pilot slice.
